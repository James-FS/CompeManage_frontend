# CompeManage 前端

CompeManage 前端是一个 Vue 3 单页应用，为学科竞赛管理系统提供操作界面。赛事、报名、获奖和评审数据均通过后端 API 读取或保存；前端的菜单和路由用于界面导航，实际身份、操作权限和数据范围由后端再次校验。

## 技术栈与环境

- Vue 3 Composition API、Vue Router 4（Hash 模式）、Pinia
- Vite 7、Element Plus、Axios
- ECharts、ExcelJS、SheetJS、SCSS
- Playwright（端到端测试）
- Node.js `^20.19.0 || >=22.12.0`

## 安装与启动

前端 Git 仓库内的 Vue 应用位于 `CompeManage` 子目录：

```bash
cd CompeManage
npm install
npm run dev
```

开发服务器默认地址为 `http://localhost:5219`，启动后打开登录页。Vite 将 `/api` 和 `/static` 请求代理到 `http://localhost:8080`，所以真实业务需要同时启动后端。

生产构建和本地预览：

```bash
npm run build
npm run preview
```

预览服务器也使用 5219 端口，并配置了同样的 API 和静态文件代理。正式部署时由部署环境提供可访问的后端 API 与 CAS 地址。

## 页面与业务流程

| 页面模块 | 页面能力 |
|---|---|
| 首页 | 根据当前用户显示入口和业务数据概览。 |
| 赛事管理 | 查看赛事目录；校级管理员新建、编辑或批量导入赛事并管理赛事年份；院级管理员在申报页提交本院赛事并查看审核进展；校级管理员审核赛事申报。 |
| 报名管理 | 学生查看赛事要求、报名并维护团队成员和指导教师；管理人员配置报名规则、审核报名信息、查看作品并审核或退回作品。 |
| 获奖管理 | 管理人员按赛事导入获奖名单、预览校验结果、查看和编辑获奖明细、处理学生补录审核；学生查看个人报名/获奖记录并申报补录；教师和赛事负责人进入“我的指导获奖”查看本人指导项目。 |
| 获奖 Excel | 获奖填报页提供附件一（获奖项目）、附件二（获奖学生）和上报汇总表导出，可选赛事举办年份；服务端按角色过滤导出数据并填写单位名称。 |
| 专家评审 | 管理人员查看评审赛事、分配专家任务、查看评审进度和评审结果；专家只查看本人任务，进入作品详情后提交评分和评语。 |
| 赛事总结 | 查看已结束赛事及总结状态；获授权的赛事负责人填写并提交其负责赛事总结。 |
| 通知管理 | 查看通知；有管理权限的人员创建、编辑、发布和删除通知。 |
| 数据统计 | 查看赛事、报名、审核、获奖及总结等汇总数据。当前前端统计页面路由允许校级管理员和院级管理员访问。 |
| 权限管理 | 校级管理员查看和分配角色权限，搜索用户、配置用户唯一角色，并为院级管理员指定管理学院。 |

获奖导入模板使用学生工号等信息匹配学生记录，指导教师按工号匹配教师；可在一个单元格中填写多位指导教师，并用常见分隔符分开。具体校验和导入范围以服务端返回的预览结果为准。

“获奖填报”列表顶部的“统一导入获奖名单”进入 `/#/award/import-all`，与单赛事导入共用预览、指导教师选择和失败名单导出功能。统一模板只增加赛事名称，不用填写赛事编号或年份；年份由后端按当前年份自动确定，页面只读展示，模板目录仅列当年可填报赛事。上传后自动匹配赛事并校验；当前年份有多个同名赛事时，可在汇总表中批量选择目标。支持按赛事查看明细、只看失败行、导入有效行，以及修正后仅重交未完成的行。弹窗修改或删除数据后，关闭弹窗会自动重新校验；同名赛事选择后也会自动校验。

## 角色菜单与数据权限

统一导入页面以赛事汇总为主，默认每页20组；标题右侧展示数量统计，表格上方提供明细、问题查看和统一提交。“查看明细”、失败数量及“查看问题”共用大弹窗，保留编辑、教师选择、删除、分页和失败名单导出。弹窗编辑仅修改本次草稿，按行标识保持当前组不跳行；关闭后自动校验，回主页面统一提交；校验请求失败时可重试。

获奖填报列表默认显示当前年份（按Asia/Hong_Kong时区），点击“重置”恢复当年筛选；仍可选择历史年份，或清空年份查看全部。列表和详情页的导入入口统一为“导入获奖名单”，列表查看入口为“查看获奖名单”。附件导出继续使用当前选择的赛事年份。

当前前端识别以下后端角色码：

| 角色 | 前端可用页面概览 |
|---|---|
| `school_admin` | 全局赛事及申报管理、报名/作品审核、获奖管理、评审管理、总结、通知、统计和权限/用户管理。 |
| `college_admin` | 本院赛事申报与审核、报名/作品审核、获奖和评审管理、总结、通知、统计。 |
| `competition_manager` | 分配赛事的报名和作品管理、获奖、评审、总结及通知；可查看赛事目录。 |
| `student` | 赛事浏览、报名和作品提交、本人竞赛与获奖补录。 |
| `teacher` | 赛事和通知浏览、本人指导获奖。 |
| `expert` | 本人评审任务、作品详情和评分。 |
| `guest` | 后端默认未分配业务权限。 |

### 院级管理员也可以担任赛事负责人

一个账号只有一个授权角色。院级管理员被校级管理员指定为赛事负责人时，角色仍为 `college_admin`，不会同时增加 `competition_manager` 角色。该院管理员可操作本人被指定负责且属于其管理学院的赛事；对本院其他赛事则按院级管理员权限查看或审核，不会拥有其他负责人的赛事编辑权。

院级管理员管理学院由后端绑定。赛事、申报、报名、获奖、文件和统计等数据由后端按相应业务规则筛选。赛事负责人角色的主要数据范围则是负责人字段关联到本人负责的赛事。学生、指导教师和专家分别受本人记录或任务分配范围限制。

前端按角色过滤菜单和路由，并在请求中携带 JWT；这不构成安全边界。API 仍会由后端检查角色权限、管理学院、赛事负责人、团队归属或专家任务。完整权限说明见[项目总览 README](../README.md)。

## 登录与 API 请求

- 开发环境使用后端用户名密码接口 `POST /api/login`。
- 生产环境由后端 CAS 统一身份认证流程处理登录。
- 登录成功后 JWT 保存在浏览器 `localStorage`，Axios 请求拦截器添加 `Authorization: Bearer <token>`。
- 收到 HTTP 401 时清理登录态并返回登录页面。
- Axios 默认超时 10 秒，文件上传使用 `multipart/form-data`。
- 前端源码中的快速填充用户仅是开发辅助信息，不保证与当前数据库账号一致。

## npm 脚本

| 命令 | 说明 |
|---|---|
| `npm run dev` | 启动 Vite 开发服务器 |
| `npm run build` | 构建生产静态文件到 `dist/` |
| `npm run build:coverage` | 生成覆盖率插桩构建 |
| `npm run preview` | 本地预览生产构建 |
| `npm run format` | 使用 Prettier 格式化 `src/` |
| `npm run test` | 运行默认 Playwright E2E 配置 |
| `npm run test:award-flow` | 使用获奖流程专用配置运行测试 |
| `npm run test:coverage` | 构建覆盖率版本并运行 Playwright/NYC 覆盖率流程 |

默认 Playwright 配置使用 Chromium、`e2e/` 目录、本地 preview 服务和 5219 端口。E2E 测试应连接对应测试后端并准备所需测试数据。仓库还提供管理员、获奖、报名和发布流程的独立 Playwright 配置文件。

## 目录结构

```text
CompeManage/
├── src/
│   ├── api/          # 后端 API 封装
│   ├── assets/       # 静态资源和全局样式
│   ├── components/   # 公共组件
│   ├── layouts/      # 主布局与空布局
│   ├── router/       # Hash 路由和导航守卫
│   ├── stores/       # Pinia 用户与登录状态
│   ├── utils/        # 请求、格式化和业务工具
│   └── views/        # 赛事、报名、获奖等业务页面
├── e2e/              # Playwright 端到端测试
├── public/           # 静态资源
├── package.json
├── vite.config.js
└── playwright.config.js
```
